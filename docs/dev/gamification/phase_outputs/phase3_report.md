## 5. Validation Logic Snippet

Status-switch block from `ReportCommandService.submitReport`:

```java
Instant now = Instant.now();
switch (session.getStatus()) {
    case PENDING:
    case CANCELLED:
        throw new DomainException(ReportErrorCode.REPORT_SESSION_INVALID_STATUS);

    case ACTIVE:
    case NO_SHOW:
        // always allowed
        break;

    case COMPLETED:
        if (now.isAfter(session.getEndedAt().plus(COMPLETED_REPORT_WINDOW))) {
            throw new DomainException(ReportErrorCode.REPORT_WINDOW_EXPIRED);
        }
        break;

    case ABORTED:
        if (now.isAfter(session.getEndedAt().plus(TERMINAL_REPORT_WINDOW))) {
            throw new DomainException(ReportErrorCode.REPORT_WINDOW_EXPIRED);
        }
        break;
}
```

Constants:
```java
private static final Duration COMPLETED_REPORT_WINDOW = Duration.ofHours(72);
private static final Duration TERMINAL_REPORT_WINDOW  = Duration.ofHours(24);
```

Validation order:
1. Load session → `SESSION_NOT_FOUND` if absent
2. Participant check → `SESSION_NOT_PARTICIPANT` if caller is not user_id_a or user_id_b
3. Self-report guard → `REPORT_SELF_NOT_ALLOWED` if `reporterId == reportedUserId`
4. Status/window switch (above)
5. Duplicate guard → `REPORT_ALREADY_SUBMITTED` if `existsBySessionAndReporter` returns true
6. Persist and return

## 8. Open Issues / Deviations

| # | Item | Decision |
|---|------|----------|
| 1 | Time-window constants (72h, 24h) | **Hardcoded** as `private static final Duration` constants in `ReportCommandService`. Not parameterized via config. Rationale: these are business rules with no per-environment variation; externalizing them to `application.yml` would add config surface area with no benefit. They can be extracted to a `ReportPolicy` class if the business needs to change them frequently. |
| 2 | `session_report.session_id` is nullable in V1 schema (FK `ON DELETE SET NULL`) | The `save()` INSERT passes `session_id` as a non-null UUID. For active sessions this is always present. No code path calls `create()` without a `sessionId`, so this is safe. |
| 3 | `ABORTED` case in the plan spec lists `ABORTED` under "terminal states … allowed within 24 hours". The gap doc also groups `CANCELLED` as terminal but excludes it from reporting. This implementation matches the gap doc exactly: `CANCELLED → REPORT_SESSION_INVALID_STATUS`, `ABORTED → 24h window`. | No deviation from spec. |
| 4 | Controller URL uses `/api/v1/sessions/{sessionId}/report` (consistent with `ReviewController` pattern of `/api/v1/sessions/{sessionId}/review`). The plan spec shows `/api/sessions/{sessionId}/report` (no version prefix). The versioned path was chosen to remain consistent with all other controllers in the codebase. | Minor deviation — intentional for consistency. |
